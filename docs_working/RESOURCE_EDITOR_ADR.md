# Resource Editor 아키텍처 결정 기록

상태: 승인됨
결정일: 2026-08-20

## 배경

655종 절차형 리소스를 브라우저에서 탐색하고, 선택한 리소스와 이름 있는 부품을
Codex에 전달해 변경 계획을 검토한 뒤 제한된 범위만 적용하는 로컬 개발 도구가
필요하다. 게임 런타임의 클라이언트 전용·오프라인 범위는 유지해야 한다.

## 결정

1. 편집기는 `?mode=editor`에서만 열리는 개발 도구이며 로컬 루프백 호스트에서만
   실행한다. 게임 프로덕션 런타임에 서버·인증·멀티플레이 기능을 추가하지 않는다.
2. 에이전트 통신은 ACP v1과 `@agentclientprotocol/sdk` 1.3.0,
   `@agentclientprotocol/codex-acp` 1.3.0으로 고정한다. 브라우저는 ACP 프로세스나
   자격 증명을 직접 다루지 않고 동일 출처 로컬 호스트의 SSE/JSON API만 사용한다.
3. 변경 요청은 읽기 전용 `plan`과 승인 후 `apply`의 두 단계로 나눈다. 계획 세션의
   쓰기·명령 실행 요청은 거부하고, 적용 세션도 현재 요청의 `assetId`, `partKey`,
   소유 소스 파일, 허용 쓰기 루트, 검증 명령으로 범위를 제한한다.
4. 승인 권한은 요청별·일회성·만료형이다. 삭제·이동·네트워크 접근·임의 셸 명령과
   선택 리소스의 소유 파일 밖 수정은 허용하지 않는다.
5. 편집기는 자동 커밋, 자동 되돌리기, 자동 배포를 하지 않는다. 적용 전 대상 파일이
   깨끗한지 확인하고, 적용 후 diff와 검증 결과를 사람이 검토하도록 남긴다.
6. Three.js 미리보기는 기존 갤러리와 공유하는 `AssetViewport`를 사용한다. 정본은
   TypeScript 팩토리이며 인스펙터의 TransformControls 값은 요청 문맥용 초안일 뿐
   소스에 직접 저장되지 않는다.

## 결과

- 에디터 호스트가 노출되는 범위와 게임 런타임의 범위가 분리된다.
- 에이전트의 쓰기와 명령 실행은 선택 문맥·승인·검증 정책을 모두 통과해야 한다.
- 기존 갤러리와 에디터가 렌더링·선택·dispose 계약을 공유해 시각 회귀를 함께
  검증할 수 있다.
- 세션 복원은 ACP 세션 ID와 브라우저의 선택·카메라·오버레이 상태에 한정하며,
  소스 변경 이력은 Git diff를 정본으로 사용한다.
